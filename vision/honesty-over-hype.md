# Honesty Over Hype

## Question
Are we being honest about stability/readiness?

## Principle
**Tier system shows stability. No false promises.**

## Applied Rules
- ✅ **Explicit tier labels** (Flagship, Experiment, Idea)
- ✅ **Visual distinction** (gestalt-based, obvious at glance)
- ✅ **Honest disclaimers** (experiments = unstable)
- ✅ **CTA matches tier** ("Use" vs "Test" vs "Follow")

## Tier Definitions

### Tier 1: Flagship
- Production-ready OR actively developed with commitment
- Full branding, detailed docs
- CTA: "Use", "Contribute", "Translate"

### Tier 2: Experiments
- Documented but unstable
- Disclaimer visible
- CTA: "Test", "Give Feedback"

### Tier 3: Ideas
- Backstage only, minimal visibility
- Ideation phase
- CTA: "Follow Progress"

## Examples

### ✅ PASS
- Tier badge on product page
- Experiment disclaimer: "Take at your own risk"
- Flagship = full color, Experiments = muted
- Honest status in README

### ❌ FAIL
- Experiment marketed as production-ready
- No tier indicator (ambiguous stability)
- Overpromising features
- Hiding instability

## Philosophy
**Honesty > hype. User knows stability at a glance.**

## When to Apply
- Product launch decisions
- Marketing copy
- README writing
- Tier promotion decisions
- Feature announcements

## Severity
**High** - Trust principle (breaks user trust if violated)
