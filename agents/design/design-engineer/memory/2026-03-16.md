### Epic Writing Guide Created

Created `~/Backstage/documentation/epics.md`:

**Key principles learned:**
- **DRY:** No `version` in YAML (folder name = truth)
- **DRY:** No `created`/`started`/`completed` (Git tracks this)
- **Minimal YAML:** Only name, goal, status, type, tasks
- **Long content:** Use separate `.md` files (index.md, notes.md, decisions.md)

**Epic lifecycle:**
```
backlog → intake → grooming → ready → done
                       ↓         ↑
                       └─────────┘ (failure: found ambiguity)
```

**Statuses:**
- `backlog` - Created, not picked up
- `intake` - Nicholas + BA write basics
- `grooming` - Agents bid, discuss until zero ambiguities (branch created)
- `ready` - Night shift execution (strict: zero tolerance for ambiguity)
- `done` - Merged to main

**Critical rules:**
- Tasks MUST use `text:` + `checked:` format (Backstage UI parser requirement)
- Version in folder name only (`epics/v4.3.0/`)
- Semantic versioning: minor (features), major (breaking), patch (fixes)
- Next version = max(existing) + 0.1.0

**When ready fails:**
- Agent encounters ambiguity → STOP immediately
- Update status back to `grooming`
- Re-open discussion, clarify, return to ready
- Zero tolerance for ambiguity in execution


### Visual Regression Discussion

**Nicholas asked:** Screenshot diff, how does it work with elastic layouts?

**Answer:** It doesn't well. Screenshot diff is brittle.

**Better approach: Code-based testing (Playwright Component Testing)**

```typescript
// Semantic assertions (not pixel diff)
await expect(component).toHaveClass('MuiButton-containedPrimary');
await expect(component).toHaveCSS('background-color', 'rgb(25, 118, 210)');
await component.click();
await expect(component).toHaveFocus();
```

**Why better:**
- Tests computed CSS (semantic, not visual)
- Handles responsive (tests breakpoint values, not pixels)
- Tests interactions (click, hover, focus)
- Self-hosted (no cloud)

**Screenshot diff = optional refinement only** (not primary validation)
