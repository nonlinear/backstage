## Problem

- Flag exists in research.py

**Example:**
```bash
python3 research.py "prisoner dilemma" --book "Philosophy and Simulation.epub"
```

## Investigation Questions

### 1. Is current metadata working for book filtering?

**Current structure:**
```
.library-index.json → topics[] → path
books/topic/path/.topic-index.json → books[] → filename
books/topic/path/.chunks.json → chunks[] → book_id
```

**Book lookup requires:**
1. Scan all topics in library-index
2. Load each .topic-index.json
3. Check if book filename matches
4. Load .chunks.json for that topic
5. Filter chunks by book_id

**Problem:** No global book index (topic-centric architecture).

---

### 2. What could we optimize for faster context finding?

**Option A: Global book index**
```json
// .library-index.json
{
  "books": {
    "Philosophy and Simulation.epub": {
      "topic": "theory_system",
      "chunks_file": "books/theory/system/.chunks.json",
      "book_id": "philosophy_and_simulation"
    }
  }
}
```

**Benefits:**
- Direct book lookup (no topic scan)
- O(1) instead of O(topics)
- Faster book-only queries

**Cost:**
- Rebuild .library-index.json on every re-index
- Duplicate metadata (topic-index + global)

---

**Option B: Fix filtering logic**

Current code (hypothesis):
```python
# Scans all topics, THEN filters by book
for topic in topics:
    load_chunks(topic)
    if book_matches:
        add_results()
```

**Better:**
```python
# Find topic FIRST, THEN load only that topic's chunks
topic = find_topic_for_book(book_filename)
load_chunks(topic)
search(chunks, query)
```

**Benefits:**
- No code architecture change
- Still uses topic-centric index
- Just smarter lookup

---

### 3. Should we index books globally?

**YES if:**
- Book-only queries are common
- Speed matters (current: 73 topic scans)
- Willing to maintain dual index

**NO if:**
- Topic queries dominant
- Index rebuild cost too high
- Prefer simpler architecture

**Recommendation:** Try Option B first (fix logic), measure improvement. If still slow → Option A (global index).
